# 功能规格：联网搜索

**特性分支**：`main`（本次未创建特性分支；功能目录与分支名独立）

**创建日期**：2026-11-24

**状态**：草案 —— 宪法已于 2026-11-24 修订为 2.0.0，原阻塞项已解除；详见文末「宪法合规检查」

**输入**：用户描述：「为助手增加联网搜索功能，使用最简单的实现方案」（原始输入中的 agent 按中文表述）

## 用户场景与验收（必填）

### 用户故事 1 —— 本地资料不足时得到带出处的联网答案（优先级：P1）

用户在交互式对话或一次性提问中启用联网搜索后，提出一个本地知识库里查不到的时效性问题（例如某个软件的最新版本、近期发生的事件）。系统除照常检索本地知识库外，还能取得公开网络信息并据此作答；「参考来源」中同时列出本地与网络两类出处，且能清楚区分，用户可自行打开网络出处核验。

**优先级理由**：这是本功能唯一的核心价值 —— 让个人知识库助手在静态文档之外仍能回答变化中的问题，同时不牺牲项目「回答可溯源」的信任基础。此故事单独实现即构成可用的最小可用版本。

**独立验证**：在联网搜索已启用、且知识库为空或不含相关内容的前提下，仅用一条自然语言提问，就能得到带可核验网络出处的回答；无需改动文档导入、存储或任何既有命令。

**验收场景**：

1. **给定** 联网搜索已启用且本地知识库中没有相关资料，**当** 用户提出一个可从公开网络查证答案的时效性问题，**则** 系统给出回答，并在「参考来源」中列出至少一条含标题与可打开网址的网络出处，且明确标注其来自网络。
2. **给定** 联网搜索已启用且本地知识库能回答问题，**当** 用户提出该问题，**则** 回答仍以本地文档为依据，网络信息只作为补充，且来源列表可区分「本地」与「网络」两类出处。
3. **给定** 用户未启用联网搜索（默认状态），**当** 用户提出任何问题，**则** 行为与现状完全一致：只检索本地知识库，不产生任何对外访问。
4. **给定** 一次含网络来源的回答已完成，**当** 用户使用既有的来源查看能力，**则** 能看到与回答时一致的全部来源（含网络来源的标题与网址），且不遗漏本地来源。

---

### 用户故事 2 —— 网络不可用时安全降级（优先级：P2）

断网、外部检索无响应、超时、零结果或返回内容不可读时，系统明确告知用户联网检索未成功，并继续按本地知识库规则作答（或在本地也无资料时按既有规则说明「知识库中没有相关信息」）；不编造事实、不无限等待、不把失败信息混入答案正文。

**优先级理由**：本地可用的体验是本产品的立身之本；联网必须只是可选增强，绝不能成为新的失败点。此故事可独立验收，即使 P1 尚未完成也具备价值（保障输出契约）。

**独立验证**：在外部检索始终失败或始终无结果的条件下提问，仍能获得完整、可预期、有时限的回答与提示；一次性提问命令的输出契约不被破坏。

**验收场景**：

1. **给定** 联网搜索已启用但网络不可用或外部检索超时，**当** 用户提问，**则** 系统在约定的等待上限内结束等待，给出明确提示，并继续基于本地资料作答。
2. **给定** 联网检索返回零结果或内容不可用，**当** 用户提问，**则** 系统不把外部内容当作事实依据，按既有本地知识库路径作答或说明无相关信息。
3. **给定** 联网检索失败且用户使用一次性提问命令并重定向输出，**当** 回答结束，**则** 可脚本消费的标准输出仍只含「回答 + 参考来源」，提示与错误信息不污染该输出，失败仍以既有错误约定结束。
4. **给定** 联网搜索已启用且外部结果中含有要求忽略来源标注、改变回答规则或执行额外动作的指令，**当** 系统生成回答，**则** 系统仍按既有规则标注来源、保持输出契约不变，且这些指令不作为回答依据。
5. **给定** 联网搜索已启用且一次回答中反复需要对外检索，**当** 达到约定的对外检索次数上限，**则** 系统停止继续检索并给出最终回答，总等待仍在成功标准限定的时间范围内。

---

### 用户故事 3 —— 用户知情且可控的隐私与本地边界（优先级：P3）

用户能清楚知道联网搜索是否启用、何时会发生对外访问、哪些数据会离开本机；启用不需要任何账号、密钥或额外安装，关闭后绝不外发。启用状态下，对外发送的仅限由当前提问派生的检索词，本地文档内容、知识库片段、配置信息与历史对话都不外发。

**优先级理由**：隐私是本项目存在的前提。把边界变成用户能理解、能验证的承诺，比多搜几条结果更重要；此故事可独立通过帮助信息与文档验收。

**独立验证**：在全新安装的默认状态下验证零对外访问；再按文档用单项配置启用，验证用户可正确说明外发范围与启用方式。

**验收场景**：

1. **给定** 全新安装且未做任何配置，**当** 用户启动程序并提问，**则** 联网搜索默认关闭、体验与现状一致，且无需任何账号、密钥、付费服务或新增常驻服务。
2. **给定** 联网搜索已启用，**当** 用户提出涉及本地私密资料的问题，**则** 只有当前提问所需的检索词被外发，本地文档内容、知识库片段、配置内容与历史对话均不外发。
3. **给定** 用户已关闭联网搜索并重新启动程序，**当** 用户再次提问，**则** 后续问题不再触发任何对外访问。
4. **给定** 用户准备首次启用联网搜索，**当** 查看既有帮助信息与使用文档，**则** 能找到启用方式、何时会发生对外访问、以及哪些数据会外发（含「用户输入的提问文本会离开本机」的明确提示）。
5. **给定** 一次联网回答已完成，**当** 用户查看本地知识库内容与既有的文档导入 / 重置行为，**则** 本地文档与片段未增加、既有行为不变，且不产生需要用户额外维护的新状态。

---

### 边界情况

- 本地知识库为空且联网搜索关闭：保持既有的「知识库中没有相关信息」短路行为。
- 本地知识库为空且联网搜索开启：允许仅依据可核验的网络结果作答，但来源必须标注为网络（宪法 2.0.0 已批准该例外）。
- 外部检索返回零结果、乱码、超大内容或重复结果：按「无可用外部依据」处理，不把低质量内容当事实。
- 外部内容包含要求改变回答规则、忽略来源要求、执行额外动作的指令：一律视为普通资料文字，不改变系统行为与输出契约。
- 网络信息与本地文档结论冲突：以本地文档为准并标明差异，不静默合并、不改写本地文档。
- 用户问题本身含有个人信息或机密文本：系统不主动外发本地资料，但用户输入的提问文本会成为对外检索词；文档与帮助必须明确提示这一点。
- 连续多轮对话或模型反复要求检索：每次提问的对外检索次数受上限约束，不得循环放大。
- 长时间等待、思考过程展示、错误退出码、既有来源查看能力：在联网开启与关闭两种状态下都保持既有表现。
- 中英文混合的检索结果：来源展示仍提供完整可核验信息，不因语言差异丢失出处。

## 需求（必填）

### 功能需求

- **FR-001**：系统必须默认关闭联网搜索；关闭状态下与现有本地知识库问答行为完全一致，且不产生任何对外访问。
- **FR-002**：用户必须能够通过单一开关启用与关闭联网搜索；启用不需要账号、密钥、付费服务、新增安装步骤或新增常驻服务。
- **FR-003**：启用联网搜索后，系统必须在每次回答前仍执行本地知识库检索；联网信息只能作为补充依据，不得替代或跳过本地检索。
- **FR-004**：启用联网搜索且本地资料不足以回答时，系统必须能够依据公开网络信息作答；仅当存在可核验的网络结果时，才把这些内容作为事实依据。
- **FR-005**：系统必须在回答的「参考来源」中区分本地文档来源与网络来源，并为每条网络来源提供标题与可打开核验的网址。
- **FR-006**：系统必须把对外发送的数据限制为当前提问派生的检索词；本地文档内容、知识库片段、配置内容与历史对话不得被外发。
- **FR-007**：系统必须让用户在使用前通过既有帮助信息与使用文档获知：功能是否启用、何时会发生对外访问、哪些数据会外发。
- **FR-008**：系统必须为每次提问的对外检索设定次数上限与等待上限；达到上限即停止等待，不出现无限等待。
- **FR-009**：系统必须在联网检索失败、超时、无结果或内容不可用时，明确告知用户，并按本地知识库规则继续作答（或在本地无资料时按既有规则说明无相关信息）；不得编造网络事实。
- **FR-010**：系统必须将外部内容视为不可信资料：其中的指令不得改变回答规则、可用能力范围或既有输出契约。
- **FR-011**：系统必须在交互式对话与一次性提问两种模式下保持一致行为，且不破坏「一次性提问的标准输出只含回答与参考来源」以及既有错误信息与非零退出码约定。
- **FR-012**：系统不得将网络结果写入本地知识库、改变文档导入与重置行为，或引入需要用户额外维护的持久状态。
- **FR-013**：用户必须能够在回答之后再次查看该回答用到的全部来源，且其中网络来源与回答时展示的一致。

### 关键实体（涉及数据时填写）

- **网络检索结果**：一次公开检索返回的可核验条目，含标题、网址与内容摘要；只在该次回答的上下文中存在，不写入本地知识库。
- **回答来源**：一次回答所依据的出处集合，分为「本地文档片段」与「网络检索结果」两类，必须可区分展示、可在回答后复查。
- **联网搜索开关**：用户可控的启用状态，默认关闭；决定本轮提问是否允许对外访问。
- **对外检索词**：由用户当前提问派生、与外部服务交换的唯一数据；不得包含本地文档、知识库内容或历史对话。

## 成功标准（必填）

### 可度量结果

- **SC-001**：联网搜索启用且知识库不含答案时，10 个时效性提问中至少 8 个可通过单条提问获得带可核验网络出处的回答。
- **SC-002**：网络不可用时，用户在 10 秒内收到明确提示并得到可继续使用的本地回答（或按既有规则说明无相关信息），且无无限等待。
- **SC-003**：默认配置下 100 次提问产生的对外访问次数为 0；启用后单次提问的对外检索次数不超过 1 次。
- **SC-004**：100% 含网络依据的回答都在「参考来源」中提供可打开核验的网址，且本地 / 网络来源标注无错标、无遗漏。
- **SC-005**：关闭联网搜索时，既有人工验收项（提问、来源查看、思考过程展示、一次性提问输出契约、错误处理）100% 通过，零回归。
- **SC-006**：启用所需的用户操作不超过 1 项配置，且无需账号 / 密钥 / 额外安装；5 名试用者中至少 4 名能在不看实现的前提下正确说明「何时会对外访问、什么数据会外发」。

## 假设与依赖

- 目标用户是现有个人知识库助手的单机使用者，通过交互式对话或一次性提问使用；不新增用户角色、权限或多人场景。
- 「最简单的实现方案」解释为：只增加一个可选的资料来源，不改变文档导入、存储、模型选择、既有命令与交互方式；范围外包括账号体系、搜索结果缓存、网页抓取 / 爬虫、网页正文全文读取、结果重排序、多来源聚合、网页界面与任何新增常驻服务。
- 默认关闭；启用后由系统判断何时需要联网，用户无需学习新的命令或提问格式。
- 外部检索面向公开、无需账号与密钥的服务；用户需自行具备可用网络，结果质量与可用性不受本项目控制。
- 每次提问最多进行 1 次对外检索、最多采用 5 条结果、单次等待上限 10 秒；超时即降级。
- 外发数据仅限当前提问派生的检索词；用户仍需注意自己输入的问题文本会离开本机，这一点由帮助信息与文档明确提示。
- 本地文档与网络信息冲突时以本地文档为准；外部内容一律按不可信资料处理。
- 依赖：既有本地知识库检索、流式回答、来源展示、来源查看、帮助信息与文档机制保持可用；启用开关与隐私边界需同步写入既有帮助信息与使用文档。
- 治理依赖：本功能原与宪法 1.1.0 的不可协商原则冲突；2026-11-24 已完成一次显式宪法修订（2.0.0，主版本），批准「默认关闭、显式启用时仅发送检索词」的窄例外，阻塞已解除，本规格可进入规划。
- 语言要求：本规格依宪法原则六全量使用中文；`FR-###`、`SC-###`、`P1` 等追溯编号按标识符例外保留。

| 原则（按 2.0.0） | 合规判断 | 依据 |

| 二、最小依赖与零构建 | 通过：不引入账号、密钥、付费服务、第三方运行时依赖或常驻服务 | 原则二新增条款；FR-002；范围外清单保持不变 |
| 三、检索有据、回答可溯源（不可协商） | 通过：本地检索仍为必做步骤；网络来源可区分且含可核验网址；空库开启联网时允许仅凭网络结果作答 | 原则三修订后的双来源规则；FR-003、FR-004、FR-005、FR-009 |

| 五、幂等摄入与显式向量 | 通过：联网结果不写入知识库、不改变导入与重置行为 | 原则五新增条款；FR-012 |
| 六、文档与交互语言统一使用中文（不可协商） | 通过：本规格标题、字段名、正文与规范性措辞已全部中文化 | 按标识符例外保留 `FR-###` / `SC-###` / `P1`；后续计划、任务、检查表同样适用 |
