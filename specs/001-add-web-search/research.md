# 第 0 阶段调研：联网搜索

**日期**：2026-11-24 | **关联**：[plan.md](plan.md) / [spec.md](spec.md)

## 调研范围与资料说明

- 本轮尝试用外部资料检索查找「无需密钥的公开检索端点」资料，检索**未返回可用结果**；
  另读取了 [SearXNG 官方搜索接口文档](https://docs.searxng.org/dev/search_api.html)，确认其
  JSON 输出需要实例侧启用 `format=json`，未开放时返回 403，且很多公开实例会关闭这些输出格式。
  [DuckDuckGo 的 API 说明页](https://duckduckgo.com/api) 未给出可用内容，不作为结论依据。
- 因此下列决策主要依据仓库现状、宪法 2.0.0 与规格约束。**默认端点可用性未实测**，
  已列为 [quickstart.md](quickstart.md) 场景 2 的首个验收项；失败一律走降级路径，不影响本地功能。
- 其余两项调研（触发方式、来源表示）基于仓库既有行为：README 已记录小模型不保证每次主动发起工具调用，
  因此首轮本地检索由 Agent 确定性执行。

## 决策 1：检索端点与解析方式

**决策**：默认使用 DuckDuckGo 的 HTML 检索页 `https://html.duckduckgo.com/html/?q=...`，
用内置 `fetch` 取回后以轻量正则提取标题、网址与摘要，并还原跳转链接中的真实网址；
端点地址由 `WEB_SEARCH_ENDPOINT` 覆盖，解析逻辑只存在于 `src/websearch.js`。

**理由**：无需账号、密钥、新依赖；单次 GET 即可获得多条可核验结果；解析失败可按「无结果」降级，
符合宪法二与 FR-002、FR-009。

**备选方案与否决理由**：

| 备选 | 否决理由 |
|---|---|
| DuckDuckGo 即时答案 JSON | 面向「即时答案」，对版本、新闻等时效性问题常无结果，难以满足 SC-001 |
| SearXNG 公开实例的 JSON 输出 | 官方文档说明 `format=json` 需实例侧启用、未开放返回 403；自建实例等于新增常驻服务 |
| 商业搜索接口（Brave / Tavily 等） | 需要密钥或付费账号，宪法二明确禁止 |
| Ollama 云端检索 | 需要云账号与密钥，且把推理链外移，违反原则一 |
| 让模型自行给出网址 | 不可核验，违反原则三 |

**风险与缓解**：该 HTML 端点不是官方接口，可能改版或限流。解析异常、超时、非成功状态一律返回空结果
并触发降级；端点常量集中在单文件，替换只需改一处；quickstart 有显式验证步骤。

## 决策 2：触发方式与外发内容

**决策**：`WEB_SEARCH=true` 时，Agent 注册一个**无参数**工具 `search_web`，模型可按需发起；
本地检索为空时由 Agent 确定性兜底执行一次；每次 `answerOnce` 内用计数器限制至多 1 次。
对外请求只带由当前用户提问派生的检索词，**忽略模型给出的任何关键词**。

**理由**：保留小模型自主补充检索的能力，又不让 P1 场景因模型不主动调用而失败；
忽略模型关键词可从根本上防止知识库片段或历史对话被拼进外发查询，满足 FR-006。

**备选方案与否决理由**：

| 备选 | 否决理由 |
|---|---|
| 启用后每次提问都确定性联网 | 外发次数增加，隐私边界更弱，FR-007 也更难解释 |
| 纯模型驱动，不做兜底 | README 已记录小模型不保证主动发起工具调用，空库场景可能直接短路 |
| 把模型生成的关键词直接外发 | 关键词可能夹带本地片段内容，违反原则一 |

## 决策 3：来源表示与输出兼容

**决策**：`sources` 数组元素增加 `kind`（`local` / `web`）；**仅当存在网络来源时**
`formatSources` 才加 `[本地]` / `[网络]` 标签，网络条目打印标题与完整网址；
关闭联网或本次回答没有网络来源时，输出与现状逐字一致。

**理由**：同时满足 FR-005、SC-004 与 SC-005 的零回归要求；`/sources` 复用同一格式化函数，
无需改动 `src/chat.js` 的来源查看逻辑。

**备选方案与否决理由**：总是加标签会改变默认输出，可能影响脚本消费；把网络来源混进本地列表则无法区分。
