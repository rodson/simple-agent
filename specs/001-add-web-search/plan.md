# 实施计划：联网搜索

**分支**：`main`（规划脚本返回 `001-add-web-search`，实际 git 分支为 `main`） | **日期**：2026-11-24 | **规格**：[spec.md](spec.md)

**输入**：功能规格来自 `specs/001-add-web-search/spec.md`

**说明**：本计划由规格工具的规划流程填写；其结构描述该流程的执行阶段。

## 摘要

在现有回答链路里增加一个默认关闭的联网补充检索：新增 `WEB_SEARCH` 开关与一个 `src/websearch.js` 模块（只用 Node.js 内置 `fetch`），启用时把公开检索结果（标题 / 网址 / 摘要）与本地片段一起交给本地模型；「参考来源」区分本地与网络两类出处。零新增依赖、零新增服务、零持久化；关闭、失败、超时一律沿用既有本地问答路径。宪法已于 2026-11-24 修订为 2.0.0，批准「默认关闭、显式启用、仅发送当前提问派生的检索词」的窄例外。

## 技术上下文

**语言 / 版本**：JavaScript（ESM），Node.js ≥ 22（沿用 `package.json` 的 `engines`）

**主要依赖**：`chromadb@3.5.x`（唯一第三方运行时依赖，不新增）；联网部分只用内置 `fetch`、`AbortSignal.timeout`、`URL`、`URLSearchParams`

**存储**：本机 Chroma（`./chroma-data/`）；网络结果只在单次回答的上下文中存在，不入库、不落盘

**测试**：无测试框架；以 [quickstart.md](quickstart.md) 与 README 既有人工验收命令为准

**目标平台**：本机命令行（Node.js ≥ 22 的 macOS / Linux / Windows）

**项目类型**：命令行工具（交互式对话 + 一次性提问两个入口）

**性能目标**：单次联网检索 10 秒上限；每问至多 1 次检索、至多 5 条结果；关闭时零额外等待、零对外请求

**约束**：`npm run ask` 的标准输出只含「回答 + 参考来源」；思考过程只到标准错误输出；错误以非零退出码结束；`package.json` 不新增运行时依赖；不引入账号、密钥或常驻服务；本地知识库检索仍是每次回答的必做步骤

**规模 / 范围**：单用户、单进程、单次提问；改动集中在 `src/config.js`、`src/websearch.js`（新增）、`src/agent.js`、`src/chat.js`，以及 `.env.example` 与 `README.md`

**待澄清项**：公开检索端点的选择（无需账号 / 密钥、能返回可核验网址）→ 已在 [research.md](research.md) 中解决；本计划不含未解决的待澄清项。

## 宪法合规检查

*门禁：第 0 阶段调研前必须通过；第 1 阶段设计后复核。依据宪法 2.0.0。*

| 原则 | 门禁结果 | 依据 |
|---|---|---|
| 一、本地优先与数据不出本机 | 通过 | 默认关闭；仅显式启用时对外检索；每问至多 1 次、10 秒、5 条；外发数据只限当前提问派生的检索词；文档、知识库片段、配置与历史对话不外发 |
| 二、最小依赖与零构建 | 通过 | 不新增依赖、账号、密钥、付费服务或常驻服务；`package.json` 不变 |
| 三、检索有据、回答可溯源 | 通过 | 首轮本地检索仍由 Agent 确定性执行；两类来源可区分并含可核验网址；空库开启联网时允许仅凭网络结果作答；外部内容按不可信资料处理 |
| 四、流式命令行与纯净标准输出 | 通过 | 失败提示不进标准输出；网络来源仍由命令行独立打印；思考过程与错误约定不变 |
| 五、幂等摄入与显式向量 | 通过 | 网络结果不写入知识库，导入 / 重置逻辑不改 |
| 六、文档与交互语言统一使用中文 | 通过 | 本计划及全部下游工件使用中文；仅标识符保留原样 |
| 复杂度门禁 | 需书面说明 | 「运行时出现对外请求」偏离本地运行，理由见下方复杂度跟踪表 |

### 第 1 阶段设计后复核

- [data-model.md](data-model.md) 未引入任何需要持久化的新实体，网络结果生命周期限于单次回答 → 原则一、五仍通过。
- [contracts/web-search.md](contracts/web-search.md) 把对外请求限定为「一次 GET、仅带检索词」，并禁止请求体、认证头与 Cookie → 原则一仍通过。
- [contracts/cli.md](contracts/cli.md) 规定关闭联网时输出逐字不变 → 原则四与 SC-005 零回归仍通过。
- 结论：**门禁全部通过**，无未说明的违规项，可进入 `/speckit-tasks`。

## 复杂度跟踪

> 仅在宪法合规检查存在需要说明的偏离时填写。

| 偏离 | 为何需要 | 更简单的替代方案为何被否决 |
|---|---|---|
| 运行时出现对外请求（偏离「本地运行」） | 规格的核心价值是回答个人知识库之外的时效性问题，必须有公开可核验来源 | 只检索本地文档无法满足 P1；让模型凭记忆给出网址违反「回答可溯源」 |
| 新增源文件 `src/websearch.js` | 把端点解析、超时、结果归一化集中一处，便于审查与替换 | 把 `fetch` 直接写进 `src/agent.js` 会让外部请求散落在回答循环里，难以验证「只发检索词」 |
| 新增两个配置项 | 用户要能显式开启；可覆盖的端点用于断网降级验收与自建兼容镜像 | 端点写死则改版必须改源码、也无法离线复现降级；只留开关则无法控制外发目标 |
| 新增无参数工具 `search_web` | 让模型按需补充检索，同时由 Agent 固定只用当前问题发起请求 | 每问都自动联网会增加外发次数；把模型生成的关键词直接外发可能夹带知识库片段，违反原则一 |
