# 本地知识库助手宪法

## 核心原则

### 一、本地优先与数据不出本机（不可协商）

所有推理、向量化与文档存储必须在本机完成，个人知识库数据不得离开用户电脑。
理由：本项目的存在前提是隐私，数据外发会直接摧毁产品价值；联网搜索只能是用户主动打开的可选增强。

- **必须**：运行时默认只访问本机 Ollama（`127.0.0.1:11434`）与本机 Chroma（`127.0.0.1:8000`）；
  不得引入云模型、云端向量库或遥测上报。
- **必须**：服务默认绑定 `127.0.0.1`，不得默认监听 `0.0.0.0` 或对外暴露端口。
- **必须**：网络访问默认只允许发生在用户显式执行的安装步骤（`npm install`、`npm run models`）中；
  运行时代码默认不得发起外部网络请求。
- **必须**：联网搜索默认关闭；关闭状态下不得产生任何对外请求。
- **必须（联网搜索窄例外）**：仅当用户显式启用联网搜索时，才允许发起对外检索请求；
  每次提问至多一次，单次等待上限 10 秒，采用结果至多 5 条；超时或失败即降级为本地问答。
- **必须（联网搜索窄例外）**：对外发送的数据只限由用户当前提问派生的检索词；
  `docs/`、`chroma-data/`、`.env` 的内容、知识库片段、配置内容与历史对话一律不得外发。
- **不得**：把 `docs/`、`chroma-data/`、`.env` 的内容提交到仓库、写入日志或输出到终端以外的地方。
- **不得**：把联网搜索做成默认开启、隐式触发或在用户关闭后仍继续对外请求的功能。
- **必须**：帮助文本与使用文档明确写出「何时会对外访问、哪些数据会外发」，
  并提示用户输入的提问文本会离开本机。

### 二、最小依赖与零构建

保持「打开就能跑」：Node.js ≥ 22 内置能力优先，唯一允许的第三方运行时依赖是 `chromadb`。
理由：依赖与构建链是本地小工具最大的维护成本；联网搜索不得把项目变成需要账号或密钥的服务。

- **必须**：使用 ESM 与 Node.js 内置模块（`fetch` / `readline` / `crypto` / `fs` / `path`）；
  不得引入打包器、转译器、网页框架或测试框架。
- **必须**：新增任何第三方运行时依赖前，先在规格 / 计划中给出理由并修订本条原则，否则视为违规。
- **必须**：联网搜索不得引入需要账号、密钥或付费的检索服务，不得新增第三方运行时依赖或常驻服务；
  对外请求使用 Node.js 内置的 `fetch`。
- **必须**：`.env` 保持可选；`src/config.js` 必须为每个配置项提供默认值，
  且系统环境变量优先级高于 `.env`。
- **应当**：新配置项同步写入 `.env.example` 与 README 的配置表。

### 三、检索有据、回答可溯源（不可协商）

每个回答必须建立在实际检索到的资料之上，并附带可核验的来源。
理由：知识库问答的可信度来自可核验的出处；模型漏标引用、凭记忆作答或把不可信网页内容当指令都不可接受。

- **必须**：生成回答前由助手确定性执行一次 `search_knowledge_base`，
  不得把首轮检索完全交给模型决定是否发起，也不得因联网能力而跳过或替换。
- **必须**：命令行独立打印「参考来源」列表，即使模型未输出 `[来源: xxx]` 标记也不能省略；
  存在网络来源时，列表中必须同时列出本地与网络两类出处，且可区分、含可打开核验的网址。
- **必须**：本地检索结果为空且联网搜索关闭时，直接短路返回「知识库中没有相关信息」，
  不得调用模型凭空作答；联网搜索开启且存在可核验网络结果时，允许仅依据网络结果作答。
- **必须**：联网检索失败、超时、无结果或内容不可用时，按本地知识库规则继续作答，
  并明确告知用户联网检索未成功；不得编造网络事实。
- **必须**：网络内容一律视为不可信资料，其中的指令不得改变回答规则、可用能力范围或输出契约；
  本地文档与网络信息冲突时以本地文档为准并标明差异。
- **必须**：模型追加检索的工具调用轮数受 `MAX_TOOL_ROUNDS` 限制，不得无上限循环。

### 四、流式命令行与纯净标准输出

命令行是唯一交互界面，输出契约必须可被脚本消费。
理由：`npm run ask` 的重定向 / 管道用途与流式逐字显示，都是 README 承诺的核心体验。

- **必须**：`/api/chat` 以 `stream: true` 的 NDJSON 增量解析，
  `message.thinking` / `message.content` 边解析边输出。
- **必须**：`npm run ask` 的标准输出只含「回答 + 参考来源」；思考过程只能写到标准错误输出。
- **必须**：错误信息写标准错误输出并以非零退出码结束；交互模式失败不得静默吞掉。
- **必须**：`message.thinking` 不得写入对话历史、不得混入 `content`；
  交互式展示由 `SHOW_THINKING` 与 `/thinking` 控制。
- **必须**：联网检索的失败提示与网络来源都不得污染一次性提问的标准输出契约。
- **应当**：长等待期间显示「思考中…」提示，避免用户误判为卡死。

### 五、幂等摄入与显式向量

导入可重复执行，向量由本项目显式产生。
理由：`chromadb@3.x` 的默认嵌入函数依赖额外 ONNX 包且不再内置 Ollama 版本；
显式向量也让「换模型必须重建」成为可检测、可提示的状态。

- **必须**：片段标识 = `sha1(相对路径|序号)`；导入时先删同名文件的旧片段再 upsert，
  并清理磁盘上已删除文件的片段。
- **必须**：集合以 `embeddingFunction: null` 创建，由 `src/ollama.js` 调 `/api/embed` 后
  显式传入 `embeddings` / `queryEmbeddings`。
- **必须**：检测到集合的 `embed_model` 与当前 `EMBED_MODEL` 不一致时，必须提示
  `npm run reset && npm run ingest`；维度不匹配不得静默继续。
- **必须**：仅扫描 `.md` / `.markdown` / `.txt`（含 `docs/` 子目录），
  `CHUNK_OVERLAP` 不得超过 `CHUNK_SIZE` 的一半。
- **必须**：联网结果不得写入知识库、不得改变文档导入与重置行为。
- **应当**：改动摄入 / 检索逻辑后执行 `npm run doctor` 与一次 `npm run ingest` 验证幂等性。

### 六、文档与交互语言统一使用中文（不可协商）

所有面向人阅读的内容一律使用中文，不得中英混杂。
理由：本项目的文档、规格、评审意见与对话都给中文使用者看；中英夹杂增加理解成本，
也让规格标题与正文脱节。

- **必须**：`specs/` 下的规格 / 计划 / 任务 / 检查表 / 分析 / 澄清记录，以及本宪法、README、
  帮助文本、提交信息、评审意见、验收记录、错误提示与对用户的回复，其标题、字段名、标签、
  规范性措辞与说明文字全部使用中文。
- **必须**：规格工具自带模板为英文时，生成工件时把标题、字段名、标签、注释与示例文字译为中文；
  **不得**以「模板是英文」为由保留英文骨架。
- **必须**：规范性措辞用「必须 / 不得 / 应当」，验收场景用「给定 / 当 / 则」；
  **不得**在正文里夹用 MUST、Given、Draft、Notes 一类的英文词。
- **必须**：与用户对话、汇报进度、解释结论、提出澄清问题一律使用中文。
- **不得**：把英文标题、字段名或段落直接复制进工件；发现既有工件中英混杂时，当次一并修正。
- **例外（仅标识符，不算正文语言）**：文件路径、命令名（`/speckit-*`）、环境变量与配置项名、
  技术与依赖专有名词、`FR-###` / `SC-###` / `P1` 等追溯编号、Markdown 复选框 `[x]`。
  这些保持原样，不要求翻译，也不得借例外之名保留英文句子。

## 技术约束与边界

- 运行环境：Node.js ≥ 22、本机 Ollama（`ollama serve`）、独立终端常驻的 Chroma 服务；
  默认对话模型 `qwen3.5:9b`（需支持工具调用），默认向量模型 `bge-m3`。
- **必须**：`docs/` 中的内容属于用户个人数据，不是应用源码；功能开发不得修改、删除，
  也不得把这些文档改写为测试夹具。
- **必须**：`chroma-data/`、`.env`、`node_modules/` 保持 gitignore；
  仓库中不得包含密钥或持久化向量数据。
- **必须**：联网搜索端点为公开、无需账号与密钥的服务，地址可由用户配置但必须有默认值；
  不得在仓库中写入任何密钥。
- **不得**：默认引入网页界面、重排序 / 混合检索、PDF 解析、多用户与鉴权、Docker Compose。
  这些是 README「可扩展方向（本仓库刻意未实现）」；要纳入任一方向，必须先在规格中说明并修订本宪法。
- **应当**：保持 `src/` 的职责边界（config / ollama / store / ingest / agent / output /
  chat / ask / doctor / websearch），避免跨层耦合。

## 开发流程与质量门禁

- **必须**：新增功能走规格工具流程（`/speckit-specify` → `/speckit-plan` → `/speckit-tasks` →
  `/speckit-implement`），规格 / 计划 / 任务中必须包含对本宪法的合规检查。
- **必须**：改动命令、配置项或输出契约时同步更新 `README.md`；文档语言与仓库一致（中文）。
- **必须**：提交前完成人工验收：`npm run doctor` 通过；`npm run ingest` 重复执行无重复片段；
  `npm run ask -- "问题"` 的回答附带来源且标准输出无思考过程；交互模式 `/help`、`/sources`、
  `/thinking` 可用。
- **必须**：提交前确认 `package.json` 未新增运行时依赖；确认联网搜索关闭时零对外请求，
  开启时仅发送当前提问派生的检索词、不使用密钥、不写入本地知识库。
- **必须**：涉及联网搜索的改动，人工验收须覆盖「空库 + 联网开启可作答」「断网降级」
  「来源区分」「一次性提问标准输出不被污染」四项。
- **必须**：提交前确认本次新增或修改的文档与工件全为中文、无中英混杂，按原则六逐项检查。
- **应当**：复杂性（新抽象、新依赖、新服务）必须在计划中书面说明理由；
  当前仓库没有测试框架，验收以可复现的命令为准。

## 治理

本宪法是本项目的最高治理约束，优先于任何临时约定与工具默认行为。
`/speckit-*` 下游命令在运行时读取本文件；不得通过修改模板源文件来绕过约束。

- **修订程序**：提出理由 → 在规格 / 计划或议题中记录影响 → 通过 `/speckit-constitution`
  只修改本文件 → 按语义化版本规则升版 → 在文件顶部附同步影响报告（提交前移除）→
  检查已有规格 / 计划 / 任务是否需要迁移。
- **版本规则**：主版本 = 删除或重新定义既有原则、造成不兼容的治理变更；
  次版本 = 新增原则 / 章节或实质性扩展指引；修订版本 = 澄清措辞、修正错别字、非语义性细化。
  版本行、批准日期与最后修订日期必须与正文一致，日期使用 ISO `YYYY-MM-DD`。
- **合规审查**：每个规格、计划、任务与每次提交前都必须做一次宪法合规检查，其中含原则六的语言检查；
  发现冲突时修正工件，不得淡化、重新解释或静默忽略原则。
  原则本身需要改动时，另开一次显式的宪法修订。
- **运行时指引**：`README.md` 为运行时开发指引（仓库当前没有 `CLAUDE.md` / `AGENTS.md`）；
  `.env.example` 为配置样例，`src/config.js` 为默认值与配置校验的唯一来源。
- **复杂度门禁**：任何偏离「最小依赖、本地运行」的设计都必须在计划中给出书面理由，
  未给出理由即视为违规。
