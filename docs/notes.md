# 技术笔记：本地 RAG（示例文档）

## RAG 的基本流程

1. 把文档切成片段（chunk），片段之间保留少量重叠，避免句子被切断。
2. 用 embedding 模型把每个片段转成向量，写入向量数据库。
3. 用户提问时，把问题也转成向量，检索最相似的若干片段。
4. 把检索到的片段连同问题一起交给大语言模型，让它只依据这些资料作答，并标注来源。

## 本项目用到的组件

- Ollama：本地跑大语言模型和 embedding 模型，提供 `/api/chat` 与 `/api/embed`。
- Chroma：向量数据库，本项目用 cosine 距离；距离越小越相似，相似度约等于 1 减距离。
- Node.js：只用内置 fetch、readline 和 crypto，唯一的第三方依赖是 chromadb 客户端。

## 排查经验

- 检索结果不相关时，先调小 CHUNK_SIZE 或增大 TOP_K，再考虑换 embedding 模型。
- 更换 embedding 模型后必须清空并重新导入，因为不同模型的向量维度不一致。
- 小模型常常不会主动输出 tool call，所以本项目由 Agent 先确定性地执行一次检索工具，再把结果交给模型；模型仍可换关键词追加检索。
